# Kamatera PostgreSQL

This Compose project runs PostgreSQL 16 and a small API in dedicated containers. PostgreSQL uses a named persistent volume and is bound only to `127.0.0.1:55432`; it is not publicly reachable. The API joins the `cavalry-books-private` Docker network, syncs the catalogue from Apps Script every five minutes, and serves the most recently successful snapshot at `/api/v1/catalog`. It also provides session-protected admin reads for documents, receipts, payment SMS, reminders, customers, and expenses. Admin list data is cached for up to two minutes (payment SMS for 15 seconds; reminders for 30 seconds), and successful admin writes through the app invalidate the cache. Public order-status reads use a 30-second cache keyed by a SHA-256 hash of the unguessable tracking token; successful admin writes invalidate this cache too. The API binds to `127.0.0.1:3100` on the VPS for Nginx reverse proxying.

The database has a 384 MiB memory limit and a 0.5 CPU limit; the API has a 192 MiB memory limit and a 0.5 CPU limit. Failed or empty catalogue syncs leave the last-known snapshot intact. Google Sheets remains the source of truth: the API verifies each staff session against Apps Script and refreshes an expired read cache from Apps Script on demand. Invoice, payment, document, production, reminder, and expense writes continue to use Apps Script; the API never records a receipt. Public order-status links are read-only bearer links; the customer page omits phone numbers and payment references. The frontend falls back to Apps Script if the API is unavailable.

The deployment generates `/opt/cavalry-bookshop-db/.env` on the server with restrictive permissions. Do not copy the password into source control, frontend JavaScript, or public documentation.

The admin portal is hosted at `https://api.cavalrypublishers.co.ke/admin/`; it skips loading the public catalogue and uses the existing Apps Script staff login. The API stores only a SHA-256 hash of registered staff session tokens. Cached admin data is returned only to an active registered session. Admin writes still go directly to Apps Script and invalidate the VPS cache after success.

Each order row stores a 64-character random tracking token in column N of `orders_log`. The shareable link opens `/admin/order-status.html#<token>`; the token stays in the URL fragment and is sent to the API in a POST body, rather than being included in browser or proxy request paths. The page shows the order items, payment totals/status, and production progress. Deploy the updated `code.gs` to Apps Script as well as the VPS API for token creation and lookup to work.

Copy `api-backend/` beside `compose.yaml` on the VPS before running `bash deploy.sh`. Install `deployment/kamatera/nginx/api.cavalrypublishers.co.ke.conf` in `/etc/nginx/sites-available/`, enable it in `sites-enabled`, create `/var/www/cavalry-api-acme`, then run `nginx -t` and reload Nginx. The API host must already resolve to the VPS and have its Let's Encrypt certificate. Copy `index.html`, `app.js`, `styles.css`, `order-status.html`, `manifest.json`, and the `favicon/` folder to `/opt/cavalry-books-admin/` for the portal's static files.

Run `bash rotate-password.sh` on the VPS to rotate the database password and recreate the containers without removing the data volume.
